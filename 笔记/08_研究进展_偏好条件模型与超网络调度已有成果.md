# 相关研究已经做到哪里：偏好条件模型与超网络调度

> 检索与整理日期：2026-10-21。本篇用于界定已有工作与自己的问题，不是完整综述。两篇附件已阅读主要方法、实验与附录，并对照关键页面；下面新增文献按可获得的原始论文页面、摘要和方法段核对。未完成这些新增方法的代码复现，不据此宣布任何方向“首次提出”。

## 1. 先修正此前对创新起点的判断

“用偏好向量输入超网络，生成调度策略参数”已经有直接研究；“共享编码器，只生成解码器末层”也已出现在多目标 FJSP 文献中。因此，之前的末层参数生成图可以保留为理解和基础对照，但不应再独立写成预期创新成果。

需要继续回答的问题是：在哪类调度条件下，现有条件化方式仍有可验证的不足？新的条件、参数生成位置或训练方式，为什么有助于解决它？仅把已有组件换一个组合名称，无法回答这两个问题。

## 2. 从通用方法到调度应用的几条线索

| 文献 | 本次核实的核心做法 | 对当前学习的意义 |
|---|---|---|
| Ha 等，*HyperNetworks*，2016 预印本 | 用一个网络生成另一个网络的权重，并端到端训练 | 参数生成是已有基本机制，不是调度领域专属概念 |
| Lin、Yang、Zhang，ICLR 2022，*Pareto Set Learning for Neural Multi-objective Combinatorial Optimization* | 单个偏好条件模型生成不同取舍的候选解，研究多目标组合优化 | “学习一族取舍”有明确方法基础；文中实验任务不能直接等同于 FJSP |
| Su 等，Swarm and Evolutionary Computation，2024，PGRL | 面向多目标 FJSP，以超网络条件化解码器，结合 ES 训练与偏好并行推理 | 是比通用超网络论文更直接的近邻工作 |
| Liu、Han，Machines，2026，DPG-GRL | 共享图表示，超网络生成两类解码器的末层；采用 PPO 与双池引导 | 末层生成、分层偏好解码、PPO 组合均已有直接参考 |
| *Preference-Conditioned Reinforcement Learning for Energy-Aware Multi-Objective Flexible Job Shop Scheduling*，Applied Sciences，2026 | FiLM 偏好调制、目标相关价值估计，并考虑可推迟安排的动作设计 | 条件化不只有生成完整权重；能耗问题还依赖动作空间和环境建模 |

这里的最后一项不能读成另一篇“相同超网络方法”：本次检索到的原文方法描述明确采用 FiLM。区分这些路线，才能设置有效对照。

## 3. 为什么 PGRL 和 DPG-GRL 会改变我的选题判断？

PGRL 的原始摘要已经明确说明：模型针对工序选择和机器分配设计编码—解码结构，超网络根据偏好生成解码器参数，并通过偏好并行推理获得候选解集。其训练使用演化策略 ES。因此，“把超网络用于多目标 FJSP”已有直接先例。

DPG-GRL 的方法段进一步明确只生成解码器最后一层，前面的层共享；原文还描述离线专家池和在线精英池。由此，先前“只生成末层以降低条件化开销”的想法更适合作为复现起点，而不能作为独立新颖性依据。

这两项判断不要求先复现论文全部表格，因为其方法描述已足以确认相同机制存在。但若要进一步声称新方案比它们更稳定、更高效或覆盖更好，就必须取得版本一致的实现并公平比较；本次尚未做到这一点。

## 4. 哪些不同不能被一句“也是多目标强化学习”抹平？

同类方法比较时，至少要对齐以下几个维度。

| 维度 | 为什么会改变结论 |
|---|---|
| 目标定义 | 总负载、最大负载、负载标准差、能耗成本分别是不同目标 |
| 动作语义 | 直接选择工序—机器对，与选择派工规则、允许推迟启动，不是同一可行策略集合 |
| 偏好输入位置 | 拼接、特征调制、末层生成、编码器条件化改变信息流的方式不同 |
| 训练方式 | ES、PPO-Clip、PPO＋KL 的数据和更新过程不同 |
| 解集预算 | 一个偏好一个解，与每个偏好采样 100 个解，不能只比较最终 HV |
| 测试分布 | 同分布新实例、未见规模、未见偏好和新生产场景是不同问题 |

特别是“支持连续输入偏好”只是一种接口能力。离散调度中，多个偏好落在同一最优安排区域是正常的；模型也可能因为没有学会区分偏好而重复输出同一安排。两者要通过相应偏好的目标质量判断，不能只数重复率。

我现在把“低重复率”作为诊断线索，而不是独立优化目标。如果强迫不同偏好输出不同安排，却导致更多被支配解，这种多样性没有实际价值。

## 5. 目前可以保留、需要降级和仍需检索的想法

**保留为实现基础：** 在现有 PPO 中接入偏好、生成共享评分器末层、让 Critic 接收偏好。这有助于理解参数生成和建立可运行的对照，但属于已有机制的落地。

**降级为普通实验因素：** 改 PPO 超参数、改变偏好采样点数、单独减少生成参数数量。它们可能影响结果，却不足以仅凭变化本身支撑方法创新。

**继续研究的候选问题：** 偏好与实例结构是否需要共同条件化；偏好对工序层和机器层的作用是否不同；只在末层调节时，前面的共享表示是否已经丢失目标相关信息。这些是从现有方法与两篇附件之间推出来的问题，仍需针对性的近邻检索和实验，而不是已确认的文献空白。

尤其不能把“本次没有找到”写成“尚无人研究”。检索已覆盖直接使用超网络的若干近邻，但不覆盖所有近年的调度、元学习、条件化 GNN 或多目标策略工作。
